Caso 01

Plataforma de gestión audiovisual

Sistema cloud para gestión segura de contenido multimedia
Sector
Sector público · Cloud · Gestión de archivos
Cliente
Gobierno de la Ciudad de Buenos Aires
Stack
Node.js · AWS S3 · Amazon Cognito · EC2 · IAM · REST API · Sharp

Contexto

Un equipo necesitaba administrar y consultar grandes volúmenes de archivos multimedia almacenados en infraestructura cloud.

Desafío

Los archivos debían mantenerse privados y estar disponibles únicamente para usuarios autorizados, evitando accesos públicos directos al almacenamiento.

Solución

Se desarrolló una arquitectura donde una API controla el acceso a los recursos, valida permisos y genera accesos temporales únicamente cuando corresponde.

Impacto

  • Archivos privados
  • Acceso controlado
  • Gestión centralizada
  • Permisos
  • Visualización segura

Caso 02 Caso confidencial

Sistema de seguimiento operativo

Una única vista operativa
Sector
Salud · Operaciones · Data
Capacidades
Seguimiento de estados · Histórico de cambios · Búsquedas · Filtros · Documentación · Exportaciones · Integración con servicios externos · Autenticación · Base de datos

Contexto

El equipo necesitaba realizar seguimiento de operaciones que dependían de información proveniente de diferentes sistemas y documentos.

Desafío

Consultar el estado de una operación requería recorrer distintas fuentes de información, dificultando el seguimiento, la detección de cambios y la consulta histórica.

Solución

Se diseñó un sistema que obtiene, normaliza y almacena información proveniente de servicios externos para transformarla en una única vista operativa.

Antes

  • Información en diferentes sistemas
  • Consultas manuales
  • Sin histórico centralizado

Después

  • Una vista operativa
  • Histórico de cambios
  • Búsqueda
  • Filtros
  • Información normalizada

Caso 03

TecWeek

De sitio estático a plataforma administrable

Plataforma digital para TecWeek con experiencia pública y backoffice para administrar contenidos, agenda, sponsors e información del evento.

Sector
Sector público · Plataforma · CMS
Stack
Next.js · Supabase · PostgreSQL · Vercel · JWT · UX/UI
Ver plataforma

Contexto

La información del evento necesitaba mantenerse actualizada durante un período de alta actividad.

Desafío

Un sitio completamente estático genera dependencia del desarrollo cada vez que cambia información operativa o editorial.

Solución

Se desarrolló una plataforma dinámica con un backoffice desde donde administrar contenidos y publicarlos sin modificar código.

Contame tu problema
  1. 01

    Entender la operación

    Primero entiendo cómo funciona el negocio, quién utiliza el sistema, qué información existe y dónde aparecen los problemas.

  2. 02

    Definir el producto

    Traduzco el problema en flujos, reglas, roles, información y funcionalidades concretas.

  3. 03

    Diseñar la experiencia

    Prototipo las partes críticas para validar cómo va a funcionar el sistema antes de llevarlas a código.

  4. 04

    Definir la arquitectura

    Modelo frontend, backend, datos, permisos, integraciones e infraestructura según las necesidades reales del producto.

  5. 05

    Construir e integrar

    Desarrollo las distintas partes como componentes de un mismo sistema.

  6. 06

    Publicar e iterar

    Deploy, validación y evolución del producto cuando empieza a utilizarse en situaciones reales.

Producto, diseño y tecnología
en una misma conversación

Los problemas de software rara vez son solamente técnicos o solamente de diseño. Por eso trabajo entendiendo ambas partes desde el comienzo.

01

Visión de producto

No empiezo por una pantalla ni por una tecnología. Primero entiendo el proceso, las reglas y qué necesita resolver el negocio.

02

Diseño + desarrollo

Las decisiones de experiencia se toman entendiendo también su impacto técnico, y las decisiones técnicas considerando a las personas que van a usar el sistema.

03

Trabajo directo

Desde la definición inicial hasta las decisiones de producto y desarrollo, trabajás directamente conmigo.
